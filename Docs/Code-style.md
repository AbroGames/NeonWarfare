# Code style conventions

[← Project README](../README.md)

## Namespaces

Namespaces mirror the path to the file: `Scenes/World/Service/Chat/WorldChatService.cs` →
`NeonWarfare.Scenes.World.Service.Chat`.

A scene and its handler live in the same folder under the same name (`Hud.tscn` + `Hud.cs`). The
`.cs.uid` files are generated by Godot — they must not be created by hand.

## Initialization

* If dependency injection is required, write `Di.Process(this)` as the **first line** in `_Ready()`
  (or in the constructor for a non-node). Without it all `[Child]` / `[Parent]` / `[SceneService]` /
  `[Logger]` will silently stay `null` — see [Dependency injection](Arch/Dependency-injection.md).
* If a node needs data **before** `_Ready()`, use the `InitPreReady(...)` method, which returns
  `this`: `PackedScene.Instantiate<Hud>().InitPreReady(world)`. For initialization after readiness —
  `InitPostReady(...)`.
* Heavy top-level initialization is split into `Init()` and `Start()`.

## Client and server

* Check the role only through `Net.*`, not through `GetMultiplayer().IsServer()` directly.
* Methods that are valid on only one side start with a check:

  ```csharp
  if (!Net.IsServer()) throw new InvalidOperationException("Can only be executed on the server");
  ```

* The `OnServer` / `OnClient` suffix in a method name denotes the side it runs on
  (`InitOnServer`, `StartSyncOnClient`, `RejectSyncOnClient`).
* Events are named `<What>Event` with the side spelled out: `SaveSuccessServerEvent`,
  `SyncEndedOnClientEvent`.

## RPC

* A public wrapper method + a private method with the `Rpc` suffix marked `[Rpc]`.
  The wrapper is a single line of the form `=> RpcId(ServerId, MethodName.XxxRpc, ...)` or
  `=> Rpc(...)`. A blank line between them is **not** inserted — this is deliberate.
* Always state the mode explicitly: `[Rpc(MultiplayerApi.RpcMode.AnyPeer, CallLocal = true)]` for
  "client → server", `[Rpc(CallLocal = true)]` for "server → client".
* Where possible, move the RPC stream onto a separate `TransferChannel` from
  `Consts.TransferChannel`.
* Arguments are Godot primitives or `byte[]` from MessagePack. JSON is not used over the network.
* Try to combine data into a single call (for example, the coordinates of several units at once)
  rather than sending an RPC per object.

More detail — in [Networking](Arch/Networking.md).

## Serialization

* Network and saves — **MessagePack** (`[MessagePackObject]`, `[Key(N)]`, `[IgnoreMember]`).
* Settings files on disk — **JSON** (`System.Text.Json`).

These two tools must not be confused: see [Data and saves](Arch/Data-and-saves.md).

## Data

* Data classes contain only state and its synchronization, without game logic.
* Models derive from `ObservableObject` + `[ObservableProperty]`; the storage subscribes to
  `PropertyChanged` and broadcasts the changes itself. Because of that, writing to a model property
  on the server is a network call, and such properties must not be used as working variables in
  loops.

## Logging

Serilog through `[Logger] private ILogger _log`, with named template parameters:

```csharp
_log.Information("Connecting to the server at {host}:{port}", host, port);
```

## Precision: float vs double

For non-critical things (visuals, auxiliary calculations) we use `float` and simply cast `deltaTime`
from `double` to `float`. For critical ones (unit stats, damage, healing, time) — `double`.

## Strings

* Error messages and templates are a `private const string` at the top of the class; at the use site
  the substitution goes through `FormatWith(...)` from Humanizer.
* Everything the player sees must be translatable — see [Localization](Localization.md).

## Memory leaks

Subscriptions to `MultiplayerApi` and service events are written as local functions so that they can
be detached correctly (`GetMultiplayer().ConnectedToServer -= ConnectedToServerEvent`). This is a
frequent cause of leaks during the Game → MainMenu transition, so such places in the code are
accompanied by a comment.

## Formatting

`.editorconfig`: UTF-8, LF, maximum line length — 120 characters.
